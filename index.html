1 Introduction

Thought seems to be structured. How can networks of connected units like neurons have structure? McCulloch and Pitts demonstrated that, under certain assumptions, artificial neural networks are equivalent to a simple propositional logic (McCulloch and Pitts 1943). So too has it been demonstrated that neural networks can exhibit the same systematic, compositional, and generative relations that psychological states are taken to have (see Fodor and Pylyshyn 1988; Smolensky 1990; and also Plate 1995; Gayler 2004). Likewise, programming languages like the linearly typed lambda calculus (Velez-Ginorio et al. 2026a; and Velez-Ginorio et al. 2026b) and LISP (Tomkins-Flanagan and Kelly 2025; Hanley, Tomkins-Flanagan, and Kelly 2025) are able to be represented in Vector Symbolic Architectures, or Hyperdimensional Computing (VSA/HDC). VSAs are a model of computation using high-dimensional vectors that support compositional, systematic, and generative patterns (Smolensky 1990; Plate 1995; Kanerva 2009; Gayler 2004). A common data structure that VSAs are required to represent are lists. In this document, we will explore two distinct methods for encoding lists in VSAs. The first, what we call Kanerva lists after Kanerva (2014); the second, we call role-filler lists, which are used in Tomkins-Flanagan and Kelly (2025) and Hanley, Tomkins-Flanagan, and Kelly (2025).

2 Lists

Definition 1 (Lists) A list of objects in set \(A\) (or, a list of \(A\)), denoted by \(\text{List}(A)\) is a set of objects recursively defined by the following conditions:

  1. \(\emptyset_A \in \text{List}(A)\); and,
  2. If \(x \in A\) and \(l \in \text{List}(A)\), then \(\text{Cons}(x, l) \in \text{List}(A)\).

def car[T](list: List[T]) -> T:
    match list:
        case Nil():
            raise ValueError("Unable to perform `car` on `nil`.")
        case Cons(head, _):
            return head


def cdr[T](list: List[T]) -> List[T]:
    match list:
        case Nil():
            raise ValueError("Unable to perform `cdr` on `nil`")
        case Cons(_, tail):
            return tail

3 VSA/HDC

VSA/HDC is a implementation of computation in high-dimensional vectors (or tensors, see Smolensky 1990) that provide neural networks with the ability to construct and manipulate distributed patterns that are compositional, systematic, and generative. Will provide a general definition of VSAs, then focus in on the two VSAs that we will use to explore list encodings: Holographic Reduced Representations (HRRs, from Plate 1995) and Time-domain Residue Hyperdimensional Computing (TRHC, counterpart to RHC from Kymn et al. 2024; cf. Voelker et al. 2021).

Definition 2 A Vector Symbolic Architecture \(\mathcal{V}\) is a structure \(\langle X^{D_1 \times \dots \times D_n}, \sim, \otimes, \oplus \rangle\), where:

  1. A pattern set \(X^{D_1 \times \dots \times D_n}\),
  2. There is a similarity function \[ x_1 \sim x_2 : X^{D_1 \times \dots \times D_n} \times X^{D_1 \times \dots \times D_n} \to [0, 1]; \]
  3. There is a binding function, \[ x_1 \otimes x_2 : X^{D_1 \times \dots \times D_n} \times X^{D_1 \times \dots \times D_n} \to X^{D_1 \times \dots \times D_n}, \] such that \(x_1 \otimes x_2\) is neither similar to \(x_1\) nor \(x_2\), and the binding operation admits an approximate inverse, \[ \begin{align*} [x_1 \otimes^{-1} (x_1 \otimes x_2) \sim x_2] &\approx 1, \\ [x_2 \otimes^{-1} (x_1 \otimes x_2) \sim x_1] &\approx 1; \end{align*} \]
  4. And, there is a bundling or superposition operation, \[ x_1 \oplus x_2 : X^{D_1 \times \dots \times D_n} \times X^{D_1 \times \dots \times D_n} \to X^{D_1 \times \dots \times D_n}, \] such that \(x_1 \oplus x_2\) is similar to both \(x_1\) and \(x_2\).

Some VSAs include an extra permutation operation that functions like a one-place binding, such that \[ \Pi(x) : X^{D_1 \times \dots \times D_n} \to X^{D_1 \times \dots \times D_n}, \] and, \[ \Pi(x) \sim x \approx 0, \quad \Pi^{-1} \Pi (x) \sim x \approx 1. \] We will not include it in our definition, but we will use the permutation operation in the following.

3.1 Holographic Reduced Representations

Holographic Reduced Representations (HRRs, Plate 1995) are a VSA defined over \(D\)-dimensional real vectors, which uses cosine similarity, element-wise multiplication in the Fourier domain, and element-wise summation to implement the VSA operations in Definition 2.

Definition 3 (HRRs) Holographic Reduced Representations (HRRs) are a VSA \(\mathcal{H}\), where

  1. The set of high-dimensional patterns is \(\mathbb{R}^D\);
  2. The similarity function is absolute cosine similarity: \[ x_1 \sim x_2 = \operatorname{abs}\left(\frac{x_1^\top x_2}{|x_1|_2 |x_2|_2}\right); \]
  3. Binding is circular convolution: \[ x_1 \otimes x_2 = \mathcal{F}^{-1}\left[ \mathcal{F}(x_1) \odot \mathcal{F}(x_2) \right], \] and unbinding circular correlation: \[ x_1 \otimes^{-1} x_2 = \mathcal{F}^{-1} \left[ \overline{\mathcal{F}(x_1)} \odot \mathcal{F}(y) \right]; \]
  4. And, bundling is the element-wise sum of \(x_1\) and \(x_2\): \[ x_1 \oplus x_2 = x_1 + x_2. \]

3.2 Time-domain Residue Hyperdimensional Computing

Time-domain Residue Hyperdimensional Computing (TRHC) is a modification of the Residue Hyperdimensional Computing VSA (RHC, Kymn et al. 2024) which uses a residue number encoding to represent natural numbers and simple arithmetic in VSAs. Strictly speaking, according to Definition 2 TRHC (and RHC) is not one single VSA but two distinct VSAs, since TRHC defines two binding operations that perform addition and multiplication over their encoded residue number. For our purposes, we will focus only on the variant with additive binding since the multiplicative binding operation is tedious to deal with.

Unlike HRRs, TRHC requires some preliminary definitions. Namely, since TRHC was developed to represent numbers using a residue encoding, we have to first define what that means.

TRHC vectors must have the following properties:

  1. TRHC vectors must have a unit norm, such that \(\|x\| = 1\); and,
  2. TRHC vectors must be unitary under binding, meaning that binding (circular convolution) and unbinding (circular correlation) must be exact inverses.

Suppose we have a set of odd moduli \(m_1, m_2, \dots, m_k\). For each modulus, let \(b_i\) denote the base vector of modulus \(m_i\) of dimension \(D\). A base vector is constructed by1:

  1. If \(D\) is even, then:
    • \(b_i[0] = 0\),
    • \(b_i[1, \dots, D / 2 - 1]\) are sampled from \(\{0, \dots, m_i - 1\}\)
    • \(b_i[D / 2] = 0\), which is the Nyquist bin; and,
    • \(b_i[D/2 + 1, \dots, D]\) is the mirror and flipped sign of \(b_i[1, \dots, D/2-1]\).
  2. If \(D\) is odd, then:
    • \(b_i[0] = 0\),
    • \(b_i[1, \dots, \lfloor D / 2\rfloor]\) are sampled from \(\{0, \dots, m_i - 1\}\), and
    • \(b_i[\lfloor D / 2\rfloor + 1, \dots, D]\) are mirror and flipped sign of \(b_i[1, \dots, D/2-1]\).

To get the residue effect, we multiply by \(2 \pi / m_i\) and exponentiate, and then apply the inverse Fourier transform to return to the time domain: \[ b_i = \exp\left( \frac{2 \pi b_i}{m_i} \right) \] For all base vectors, let \(b_i^n\) denote: \[ b_i^n = \mathcal{F}^{-1} \left[ \mathcal{F}(b_i)^n \right]. \] Then, the encoding of a natural number \(n\) in TRHC with moduli \(m_1, m_2, \dots, m_k\) is: \[ v(n) = b_1^n \otimes b_2^n \otimes \dots \otimes b_k^n, \] where \(\cdot \otimes \cdot\) denotes circular convolution. This gives us the residue result, such that each vector stores the residues \(n \bmod m_1, \dots, n \bmod m_k\), and by the Chinese Remainder Theorem, \(n\) is uniquely determined modulo \(\prod_i m_i\).

Definition 4 (Additive Time-domain Residue Hyperdimensional Computing) Additive Time-domain Residue Hyperdimensional Computing2 (aTRHC) is a VSA with:

  1. A set of \(D\)-dimensional real vectors, \(\mathbb{R}^D\);
  2. Binding via circular convolution, unbinding via circular correlation; and,
  3. Bundling via element-wise addition.

aTRHC is said to be additive because circular correlation obeys the following property: \[ v(n) \otimes v(m) = v\left(n + m \bmod \prod_i m_i\right). \]

4 VSA Lists

So far all we have seen is how to define a VSA. This is useful for investigating the features of VSAs, but purely giving definitions does not give an intuitive feel for how to use VSAs in defining networks. Recall that, by Definition 1, lists are made up of two kinds of objects: \(\operatorname{Nil}_A\), denoting the empty list, and \(\operatorname{Cons}(x, l)\), denoting the combination of \(x\) with the list \(l\).

Atomic objects like \(\operatorname{Nil}_A\) are represented in VSAs by randomly sampled vectors from the pattern set of the VSA. For ease of use, we store them in maps called codebooks, \(\mathsf{C}\), and index the vectors by names3. Let \(\mathbf{nil}\) be sampled in the pattern set of some VSA, \(\mathcal{V}\).

There are many potential ways for getting equivalent behavior to the constructor \(\operatorname{List}(x, l)\). In the following, we will investigate three options: a naïve encoding that combines elements by binding; the Kanerva encoding, which combines elements by permutations; and the role-filler encoding, which tags elements by a role vector symbol.

4.1 ❌ Naïve encoding

The naïve encoding of lists is a straightforward, though memory intensive, method for mirroring the behavior of lists. Recall, we have already defined a vector symbol \(\mathbf{nil}\). Let \(\mathbf a, \mathbf b, \dots\) be more arbitrary vector symbols from the pattern set of our VSA. To perform the naïve encoding, we can encode a list as a plain binding: \[ \operatorname{cons}_\text{Naive}(\mathbf a, \mathbf b) = \mathbf{a} \otimes l \] where \(l\) is some previously bound expression. To destruct a list expression, consider the first case where \(l = \mathbf{nil}\). Then, we can test if \(l \sim \mathbf{nil} > \theta\), for some arbitrary threshold \(\theta\). For the case where \(l = \mathbf{a} \otimes l'\)4, the head can be retrieved by unbinding \(l\) by \(l'\); and the tail can be retrieved by unbinding \(l\) by \(\mathbf a\): \[ \begin{align*} \operatorname{car}_\text{Naive}(l) &= l' \otimes^{-1} (\mathbf a \otimes l'), \\ \operatorname{cdr}_\text{Naive}(l) &= \mathbf a \otimes^{-1} (\mathbf a \otimes l'). \end{align*} \]

The naïve approach can be operationalized using HRRs as follows:

np.random.seed(41)
D = 5_000
theta = 0.3 # High theta because we don't use cleanup memories
nil = HRR.new(D)
a = HRR.new(D)

# Constructing the list
l = a * nil
# List should be a distinct object from a and nil
assert(l.sim(a) < theta)
assert(l.sim(nil) < theta)

# Destructing the list
head = l / nil
assert(head.sim(a) > (1 - theta))
tail = l / a
assert(tail.sim(nil) > (1 - theta))

Of course, while this approach is easy, it is not practical.

A desirable property of VSA networks is that we should be able to use and manipulate structured patterns while knowing as little information about the vector symbol as possible.

Desideratum 1 (Encoding parsimony) A VSA encoding for some data structure should be able to achieve parity with the abstract definition while using the least amount of information as possible.

For example, suppose that we have some list \(l\) and we do not know what elements it is composed of. VSAs, by nature, are opaque as to their contents without additional help. For example, we could decode the elements of the vector using a resonator network (Frady et al. 2020), but this would defeat the purpose as we would already retrieve a fully factorized list. Another option would be to memoize arguments to the list constructor upon each call. However, once again, given an arbitrary \(l\), how would we recover the head? Therefore, we must conclude that the naïve encoding is not a worthwhile encoding scheme for lists that have arbitrary members.

4.2 ✅ Kanerva encoding

A similar lightweight intuition motivates what we call the Kanerva encoding (from Kanerva 2014), and fares better against Desideratum 1. We will include the previous \(\mathbf{nil}, \mathbf a, \mathbf b, \dots\) in our codebook. Further, we will use three additional operations: the left permutation \(\Pi_\leftarrow\), the right permutation \(\Pi_\rightarrow\), and cleanup memory \(\mathcal{M}\) where: \[ \begin{align*} \Pi_\leftarrow &: X^{D_1 \times \dots \times D_n} \to X^{D_1 \times \dots \times D_n}, \\ \Pi_\leftarrow &: X^{D_1 \times \dots \times D_n} \to X^{D_1 \times \dots \times D_n}. \end{align*} \] The left permutation and right permutation also have approximate inverses defined for them, denoted by \(\Pi_\leftarrow^{-1}\) and \(\Pi_\rightarrow^{-1}\) respectively. The cleanup memory \(\mathcal{M}\) can be any autoassociative memory.

With left and right permutations defined, list construction in the Kanerva encoding for vector symbol \(\mathbf{a}\) and list \(l\) is: \[ \operatorname{cons}_\text{Kanerva}(\mathbf a, l) = \Pi_\leftarrow(\mathbf a) \oplus \Pi_\rightarrow(l). \] For deconstruction, we will ignore the \(\mathbf{nil}\) case as it is identical to the naïve encoding. In the case that \(l = \Pi_\leftarrow (\mathbf a) \oplus \Pi_\rightarrow(l)\), then: \[ \begin{align*} \operatorname{car}_\text{Kanerva}(l) &= \Pi^{-1}_\leftarrow(l), \\ \operatorname{cdr}_\text{Kanerva}(l) &= \Pi^{-1}_\rightarrow(l). \end{align*} \] The cleanup memory \(\mathcal{M}\) can optionally be applied to the result of \(\operatorname{car}_\text{Kanerva}\) or \(\operatorname{cdr}_\text{Kanerva}\). By the distributive properties permutation and the properties of bundling, it should be the case that \(\Pi^{-1}_\leftarrow(l)\) is closer to \(\mathbf a\) than anything else5.

Our method can be operationalized by the following:

def inv_perm(perm):
    inv = np.arange(perm.size) # initialize inv
    inv[perm] = np.arange(perm.size) # create inv from perm
    return inv

rightperm = np.random.permutation(D)
leftperm = np.random.permutation(D)
assert(not np.allclose(rightperm, leftperm))

def kanerva_cons(hd, tl):
    hd = hd.data[leftperm]
    tl = tl.data[rightperm]
    return HRR.from_array(hd + tl)


def kanerva_car(xs):
    return HRR.from_array(xs.data[inv_perm(leftperm)])

def kanerva_cdr(xs):
    return HRR.from_array(xs.data[inv_perm(rightperm)])

l = kanerva_cons(a, nil)

hd = kanerva_car(l)
assert hd.sim(a) > (1 - theta)

tl = kanerva_cdr(l)
assert tl.sim(nil) > (1 - theta)

How does our method fair against Desideratum 1? It is clear to see that if we have an arbitrary vector, as long as we have the basic symbols stored in our codebook, we can recursively destruct any list to recover the atomic constituent elements. The only downside is that we must rely on bundling, which might be lossy6.

4.3 ✅ Role-filler encoding

The final list encoding strategy that we will investigate is the role-filler pair (RFP) strategy. Role-filler pairs are motivated by a similar idea: given arbitrary lists, how do we recover the constituent components? Instead of defining new permutation operators, the RFP strategy defines new atomic vector symbols to stand as roles.

Let us have the same codebook as our Kanerva strategy, so \(\textbf{nil}, \textbf a, \dots\), as well as two new symbols: \(\mathbf{left}\) and \(\mathbf{right}\). Furthermore, let us store all atomic symbols in a cleanup memory \(\mathcal{M}\). Then, list construction is as follows: \[ \operatorname{cons}_\text{RFP}(\mathbf a, l) = (\mathbf a \oplus \mathbf{left}) \otimes (l \oplus \mathbf{right}). \] The filler values are identified by the varying elements in the structure. We can rely on both the properties of bundling and binding to recover elements in the list: \[ \begin{align*} \operatorname{car}_\text{RFP}(l) &= \textbf{right} \otimes^{-1} l, \\ \operatorname{cdr}_\text{RFP}(l) &= \textbf{left} \otimes^{-1} l. \end{align*} \] For our example above, applying if \(l = \operatorname{cons}_{\text{RFP}}(\mathbf a, \mathbf{nil})\), then: \[ \begin{align*} \operatorname{car}_\text{RFP}(l) &= \textbf{right} \otimes^{-1} l \approx \mathbf a \oplus \textbf{left} + \kappa \\ \operatorname{cdr}_\text{RFP}(l) &= \textbf{left} \otimes^{-1} l \approx \mathbf{nil} \oplus \textbf{right} + \kappa, \end{align*} \] where \(\kappa\) is noise.

This can be operationalized as:

left = HRR.new(D)
right = HRR.new(D)


def cons_rfp(x, y):
    return (x + left) * (y + right)


def car_rfp(xs):
    return xs / right


def cdr_rfp(xs):
    return xs / left


l = cons_rfp(a, nil)

hd = car_rfp(l)
assert hd.sim(a + left) > 0.5

tl = cdr_rfp(l)
assert tl.sim(nil + right) > 0.5

4.4 Comparing RFP and Kanerva encodings

How do we weigh the two encodings against one another? If our only concern was Desideratum 1, then one does not outweigh the other as they both define two additional objects. However, there is something to note about the RFP encoding. Repeated bindings are purportedly lossy. In order to combat this, one can introduce a pointer mechanism (see Tomkins-Flanagan and Kelly 2025; Hanley, Tomkins-Flanagan, and Kelly 2025). But this, strictly speaking, means that there are more objects involved (a new pointer allocation and storage mechanism). Therefore, we ought to prefer the Kanerva encoding if chosen without any other considerations.
